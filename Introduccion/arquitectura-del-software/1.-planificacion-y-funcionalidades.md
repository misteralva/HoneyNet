# 1. Planificación y funcionalidades

## Matriz de requisitos y funcionalidades

Cada función tiene una prioridad según su impacto en el MVP, un disparador concreto y una fecha aproximada de entrega.

| ID | Prioridad | Objetivo | Funcionalidad | Disparador | Estado |
|---|---|---|---|---|---|
| ID1 | Alta | Presentar la empresa y su servicio | Web pública | Al abrir la URL se reproduce el vídeo y, al terminar, se redirige a Inicio | Pendiente |
| ID2 | Alta | Captar clientes interesados | Formulario de contacto que guarda el mensaje en la base de datos y muestra una confirmación | Clic en el botón «Enviar mensaje» | Pendiente |
| ID3 | Media | Mostrar los planes de contratación | Página de planes con tarjetas cargadas desde la base de datos (nombre, precio mensual y características) | Carga de `/planes` o clic en el botón de Inicio | Pendiente |
| ID4 | Media | Administrar el sitio de forma segura | Login de administrador | Botón de acceso en la barra de navegación, que lleva a la pantalla de login | Pendiente |
| ID5 | Media | Consultar los ataques capturados | Panel de administración con una tabla de logs, que es un panel de Grafana alimentado por Wazuh | Inicio de sesión como administrador | Pendiente |
| ID6 | Media | Visualizar estadísticas de los ataques | Gráficos de Grafana incrustados en el panel de administración (nginx actúa de proxy hacia Grafana, solo desde la red interna) | Clic en la pestaña «Gráficos» tras iniciar sesión | Pendiente |
| ID7 | Alta | Acceder a la web por un dominio propio | DNS (Bind9) que resuelve el dominio interno del proyecto (`honeypot.lan`) hacia el servidor web | El navegador del cliente consulta el nombre de dominio | Pendiente |
| ID8 | Alta | Asignar direcciones IP | DHCP en `ct-dns-dhcp`, con relay en pfSense y rango dinámico protegido (.100 a .200) | Arranque del cliente | Pendiente |
| ID9 | Alta | Publicar la web a través del gateway | Reenvío de puertos en pfSense desde la WAN hacia el puerto web del servidor | Petición HTTP/HTTPS que llega a la interfaz WAN | Pendiente |
| ID10 | Alta | Proteger los servidores | Cortafuegos UFW con mínimo privilegio (la base de datos solo acepta al servidor web) y SSH con claves | Arranque del servidor o intento de conexión | Pendiente |
| ID11 | Media | Proteger los datos ante pérdidas | Copias de seguridad nocturnas de la base de datos y de las configuraciones con rsync y cron | Tarea programada a las 03:00 | Pendiente |
| ID12 | Baja | Usar el sitio desde cualquier dispositivo | Diseño responsive | Carga de la web desde un móvil o una ventana estrecha | Pendiente |
| ID13 | Alta | Llevar el control de versiones | Repositorio Git en GitHub con el código y la documentación | Cada `git push` | Pendiente |

## Leyenda

- **Prioridad**: Baja, Media o Alta, según el impacto en el MVP del proyecto.
- **Requisito**: qué necesita el cliente o el usuario.
- **Funcionalidad**: cómo el software va a resolver esa necesidad.
- **Disparador**: acción (clic, carga de página, tarea programada) que inicia la función.
- **Estado**: Activo, Pendiente o Cancelado.
