# 2. Arquitectura del sistema

## Identificación de componentes

La arquitectura es **cliente-servidor**: el cliente (navegador) pide páginas al servidor web, que ejecuta la lógica de negocio y consulta la base de datos.

| Componente | Tecnología | Versión | Puerto | Descripción de uso o requisitos |
|---|---|---|---|---|
| **Hardware** | PC 1 y PC 2 del centro (PC 1: Intel i5-8500, 8 GB de RAM, SSD de 128 GB y una tarjeta de red; PC 2: una tarjeta de red, resto por confirmar) y switch HP 1810-24 | no | no | Material del centro, sin posibilidad de ampliarlo. El reparto de recursos está en [Infraestructura física](../infraestructura-fisica.md). |
| **Sistema operativo** | Proxmox VE como hipervisor en los dos PCs (libre); Debian GNU/Linux en los contenedores y en la VM cliente (libre); pfSense CE en una VM (libre) | Proxmox VE 9; Debian 13 (Trixie) | no | Debian 13 es estable y ya se usa en las prácticas de DNS. Proxmox VE 9 se basa en Debian 13. |
| **Interfaz de usuario (Frontend)** | HTML5, CSS3, JavaScript y Bootstrap | Bootstrap 5.3 | 80 / 443 | Páginas responsive servidas por nginx: vídeo principal, Inicio, Sobre nosotros, Sectores, Planes, Contacto y panel de administración. |
| **Lógica de negocio (Backend)** | PHP con PHP-FPM | PHP 8.4 | Socket Unix | Procesa el formulario de contacto, carga planes y sectores desde la base de datos y gestiona el login del administrador. Se elige PHP por la experiencia previa con PHP y MySQL. |
| **Servidor web** | nginx en el contenedor `ct-web` (VLAN 60) | 1.26 | 80 y 443 | Sirve los archivos estáticos, pasa los `.php` a PHP-FPM y hace de proxy hacia Grafana en `/grafana/`. Dominio interno `honeypot.lan`. |
| **Base de datos** | MariaDB en el contenedor `ct-db` (VLAN 20) | 11.8 | 3306 | Guarda planes, sectores, mensajes de contacto y usuarios. Solo acepta conexiones del servidor web. Los ataques capturados no se guardan aquí. |
| **Ataques y gráficos** | Wazuh (registra los ataques) y Grafana (los muestra), en la VM SIEM de la VLAN 30 | Versión estable actual | 3000 (Grafana) | Los paneles de Grafana, incluida la tabla de logs, se incrustan en `/admin` a través del proxy de nginx. |
| **Sistema gestor de base de datos** | MySQL Workbench en el equipo del administrador | 8.0 | 22 | Diseño del modelo E-R y administración de la base de datos sin abrir el puerto 3306 a la red. |

## Justificación de la elección tecnológica

- **Debian 13**: estable, libre y ya conocido por las prácticas de DNS; sus paquetes incluyen nginx 1.26, PHP 8.4 y MariaDB 11.8.
- **nginx**: ligero y rápido para servir una web con PHP; consume muy poca memoria, algo clave con solo 8 GB de RAM por PC.
- **PHP 8.4 con PHP-FPM**: lenguaje ya trabajado en otros proyectos (PHP/MySQL) y con PDO para consultas preparadas.
- **MariaDB 11.8**: es el servidor compatible con MySQL que incluye Debian 13.
- **Wazuh y Grafana para los ataques**: Wazuh ya recoge y correlaciona los logs de los honeypots, y Grafana los visualiza. Así no hace falta un script propio ni una tabla de ataques en la base de datos de la web, y la DMZ no tiene que conectarse a ninguna base de datos.
- **Bootstrap 5.3**: permite un frontend responsive sin escribir todo el CSS a mano.
- **Contenedores LXC**: comparten el kernel de Proxmox y arrancan con muy poca RAM, lo que permite separar cada servidor aplicando el mínimo privilegio entre ellos.
